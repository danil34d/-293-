## Рабочая схема

### Вариант 1. Локальная Wi-Fi сеть

Используется, если телефон и Linux-сервер в одной сети:

- вход: `http://192.168.1.36:3000/login`
- мониторинг: `http://192.168.1.36:3000/wallboard`

Плюсы:

- самый простой путь
- не требует Tailscale на телефоне

Минусы:

- это не лучший вариант для Android PWA
- на обычном HTTP service worker не должен работать на чужих устройствах
- установка "как приложение" на Android будет ограничена

### Вариант 2. Android + Tailscale + HTTPS

Текущий рекомендованный путь:

- установить Tailscale на Android
- войти в тот же tailnet
- открыть `https://carwash-usb.tail34f21a.ts.net/login`
- установить сайт на главный экран из Chrome

Плюсы:

- HTTPS
- tailnet-only доступ
- можно использовать как приложение
- не надо открывать проект в интернет

Минусы:

- на телефоне нужен Tailscale

### Вариант 3. Отдельный APK

Технически возможен через Trusted Web Activity / Bubblewrap.

Что даст:

- Android APK-файл для ручной установки
- иконка и launcher как у обычного приложения

Чего не даст:

- APK сам по себе не решит сетевой доступ
- вне Wi-Fi все равно нужен Tailscale или публичный HTTPS

## Почему сейчас не выбран APK

Сначала нужно проверить, что сотрудникам удобен сценарий:

- открыть HTTPS-адрес
- войти
- поставить на экран

Если этот сценарий устраивает, отдельный APK может оказаться лишней сложностью.

## Когда возвращаться к теме APK

Имеет смысл делать APK, если:

- нужен branded Android installer
- нужно массово раздавать один файл сотрудникам
- хочется убрать визуальное ощущение "это браузер"

## Следующий шаг

Если возвращаемся к теме Android APK, делать так:

1. Зафиксировать конечный HTTPS-адрес приложения.
2. Зафиксировать стартовый маршрут: `/login`.
3. Подготовить отдельную TWA/Bubblewrap-оболочку.
4. Собрать подписанный APK.
5. Проверить установку на Android вне dev-среды.
