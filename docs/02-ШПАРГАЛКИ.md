# Шпаргалки

## 1) Быстрый старт (Windows)

```bat
START.bat
```
или
```powershell
./START.ps1
```

Остановка:
```bat
STOP.bat
```
или
```powershell
./STOP.ps1
```

## 2) Порты
- Frontend: по умолчанию `3000`, fallback `3001..3005`
- Backend: по умолчанию `8080`, fallback `8081..8085` (только при `USE_GO_BACKEND=true`)
- Фактический адрес всегда печатается в выводе `START.ps1` / `START.bat`

## 2.1) Telegram Worker
- Запускается вместе с `START.ps1` как отдельный процесс.
- Логи worker: `%TEMP%\carwash_telegram_bot.log`
- PID worker: `%TEMP%\carwash_telegram_bot.pid`
- Общие настройки приложения: `.env.local` в корне (включая `TELEGRAM_BOT_SECRET`).
- Локальная конфигурация worker: `telegram-bot/.env.local`
- Ручной запуск:
```bash
npm run bot:telegram
```
- Отключить worker:
```env
TELEGRAM_BOT_ENABLED=false
```

## 6) Диагностика

### Если не открывается сайт
1. Выполнить `STOP.bat`.
2. Снова запустить `START.bat`.
3. Проверить адрес frontend из вывода `START.bat` (`3000` или один из `3001..3005`).

### Если проект уже был запущен и стартовали повторно
1. `START.ps1` сам остановит предыдущую копию проекта из этой рабочей папки.
2. Чужие процессы на `3000/8080` не останавливаются автоматически.

### Если backend не отвечает
1. Проверить `http://localhost:8080/health`.
2. Проверить Go: `go version`.

### Если OCR не работает
1. Проверить Python: `python --version`.
2. Установить OCR зависимости: `pip install -r scripts/plate_requirements.txt`.
3. Проверить API запросом с `-F image=@...`.

## 8) Счета (`/invoices`)
- Контрагенты и агрегаторы в списке выбора показываются всегда.
- Если после выбора клиента нет строк в акте, значит за выбранный период нет моек с привязкой к этому клиенту.
- Для контрагентов проверяйте, что в мойке выбрана форма оплаты `counterAgentContract`.
- Для агрегаторов проверяйте, что в мойке выбрана форма оплаты `aggregator`.

## 9) Рутинная проверка проекта
```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\health-check.ps1
```

Проверяет:
- страницы из главного меню;
- ключевые API;
- `/api/auth/login` (валидный и невалидный JSON);
- `/api/auth/me` без авторизации (ожидается `401`);
- health Go backend (`http://127.0.0.1:8080/health`) только если `USE_GO_BACKEND=true`.

В корневом `.env.local`:

## 14) График смен и планирование (быстрый сценарий менеджера)

1. Открыть планирование: `http://localhost:3000/schedule/planning`
2. Открыть нужный план (месяц)
3. (Опционально) Если сотрудники меняли предпочтения в `/employee/schedule` после создания плана: режим `Сотрудники плана` → `Синхронизировать значения` (или включить синхронизацию прямо в диалоге автозаполнения)
4. Перейти в режим `Требования по дням`
5. Быстро заполнить требования:
- выделить дни (Все/Будни/Выходные)
- применить пресет `Норма: 2 (бокс 1 день)` или `Погода: 1 (бокс 1 день)`
- для “закрыто” использовать `Закрыто: 0` (будет сохранено как явное требование `requiredCount=0`)
6. Погода (Вязники):
- нажать `Загрузить прогноз`
- (опционально) `Выделить “погоду”`
- `Заполнить пустые дни` (не трогает уже заданные требования)
7. Запустить автозаполнение смен:
- в списке планов нажать `Автозаполнить`
- при необходимости оставить включенным `Подтянуть настройки сотрудников из предпочтений`
- в toast нажать `Открыть график`
8. Проверка в графике:
- `http://localhost:3000/schedule?month=YYYY-MM`

Примечание: прогноз ограничен ближайшими днями. Даты без прогноза заполняются как “Норма: 2”.

Журналы/файлы:
- Погодные рекомендации (best-effort): `data/_meta/pattern-journal/weather-recommendations-YYYY-MM.json`
- Журнал месяца (мойки+смены+погода): `data/_meta/pattern-journal/monthly-YYYY-MM.json` (создаётся кнопкой `Собрать журнал` или `GET /api/pattern-journal/month?month=YYYY-MM`)
- `POST /api/telegram/internal/shift-swap/respond`

WebApp-вход сотрудника:
- `GET /api/telegram/webapp-login?token=...`
- при валидном токене ставится cookie и выполняется переход на `/employee/workstation`.

Проверка `/wash` end-to-end:
1. У сотрудника должна быть смена на сегодня (иначе `/wash` блокируется).
2. В Telegram отправить `/wash`.
3. Выбрать команду -> ввести номер (или отправить фото).
4. Выбрать оплату и клиента (агрегатор/контрагент при необходимости).
5. Выбрать услуги, добавить комментарий и подтвердить.
6. Проверить, что в `data/wash-events` появилась запись, а в `data/stock-movements` создано движение расхода химии.

Проверка WebApp-сценария:
1. В Telegram отправить `/workstation`.
2. Нажать `🚿 Открыть рабочую станцию`.
3. Убедиться, что открылась `http://localhost:3000/employee/workstation` без ручного логина.
4. В локальном `http://` режиме кнопка откроет внешний браузер (это нормально, `web_app` внутри Telegram требует `https://`).
