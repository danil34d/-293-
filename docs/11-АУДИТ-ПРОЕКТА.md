## Общая оценка

Проект функционирует и компилируется без ошибок TypeScript. Однако обнаружены серьёзные проблемы в безопасности, обработке ошибок и бизнес-логике. Найдено **51 проблема**: 7 критических, 13 высокого уровня, 13 среднего, 18 низкого.

---

## КРИТИЧЕСКИЕ ПРОБЛЕМЫ (7)

### 1. Аутентификация через cookie без подписи

**Файл:** `src/lib/server-auth.ts`

Cookie `employee_auth_sim` содержит полный JSON объекта сотрудника. Пользователь может:
1. Расшифровать cookie (он не зашифрован, просто JSON)
2. Заменить `role: "employee"` на `role: "admin"`
3. Получить полный административный доступ

**Что делать:** Подписывать cookie через HMAC или использовать серверные сессии.

---

### 2. Пароли хранятся и передаются в открытом виде

**Файл:** `src/app/api/auth/login/route.ts`

Пароли в `data/employees/*.json` — чистый текст. При логине пароль попадает в cookie. Endpoint `/api/auth/me` пытается удалить пароль через `delete`, но это ненадёжно.

**Что делать:** Хешировать пароли (bcrypt), никогда не класть пароль в cookie.

---

### 3. Telegram API возвращает пароли

**Файл:** `src/app/api/telegram/internal/employee-credentials/route.ts`

Endpoint возвращает username и password в открытом виде по chat_id. Если бот скомпрометирован — все пароли утекут.

**Что делать:** Возвращать временный токен вместо пароля.

---

### 4. Ошибка округления в расчёте зарплат

**Файл:** `src/services/salary-calculator.ts`

Используется `parseFloat(earning.toFixed(2))` — при большом количестве моек ошибки округления накапливаются. За месяц разница может составить десятки рублей на сотрудника.

**Что делать:** Считать в копейках (целые числа), округлять только при выводе. Или использовать `Math.round(value * 100) / 100`.

---

### 5. Гонка состояний при создании мойки

**Файл:** `src/services/wash-event-create-service.ts`

Между проверкой существования файла и записью — окно для дубликата. Два одновременных запроса могут создать два wash-event с одним ID → двойные начисления.

**Что делать:** Использовать атомарные операции записи (`fs.writeFile` с флагом `wx`) или блокировку файлов.

---

### 6. Гонка в отправке черновиков

**Файл:** `src/services/wash-registration-service.ts`

Объявлена `inFlightDraftSubmits` Map для дедупликации, но она никогда не используется. Два запроса с одним draftId могут пройти одновременно.

**Что делать:** Реализовать проверку через `inFlightDraftSubmits.has(draftId)` перед обработкой.

---

### 7. useToast — бесконечный цикл

**Файл:** `src/hooks/use-toast.ts`

`state` в массиве зависимостей useEffect вызывает бесконечный ре-рендер. Утечка памяти, лишние подписки.

**Что делать:** Убрать `state` из зависимостей: `}, []`.

## ВЫСОКИЙ УРОВЕНЬ (13)

### 8. Гонка состояний при записи JSON файлов

**Все роуты с PUT/POST**

Файловая БД без блокировок. Два запроса → один перезаписывает изменения другого. Это касается: инвентаря, транзакций, расписания, расходов.

**Что делать:** Ввести файловые блокировки или перейти на SQLite.

---

### 9. Нет лимита на размер изображения OCR

**Файл:** `src/app/api/recognize-plate/route.ts`

Base64-картинку декодят без проверки размера (только минимум 100 байт, максимума нет). Можно отправить 1 ГБ картинку и уронить сервер.

**Что делать:** Добавить `MAX_IMAGE_SIZE = 10 * 1024 * 1024` (10 МБ).

---

### 10. Bulk DELETE OCR без проверки роли

**Файл:** `src/app/api/ocr-failed/route.ts`

`DELETE ?all=1` удаляет все OCR-файлы, но проверяет только `requireAuth()`, а не `requireAdmin()`. Любой сотрудник может стереть все ошибочные фото.

---

### 11. GET /api/employees без аутентификации

**Файл:** `src/app/api/employees/route.ts`

Список всех сотрудников (с именами, телефонами) доступен без логина. То же для `/api/aggregators`.

---

### 12. Тихий сбой при обновлении баланса клиента

**Файл:** `src/lib/client-balance.ts`

Ошибка записи баланса ловится, но не прокидывается наверх. Клиент думает оплата прошла, а баланс не обновился.

---

### 13. Ошибка в логике обмена сменами

**Файл:** `src/services/shift-swap-service.ts`

При обмене сменами удаление сотрудника из слота может не сработать из-за нормализации ID. Итог — оба сотрудника в одной смене, двойные начисления.

---

### 14. AuthContext — сломанный logout

**Файл:** `src/contexts/AuthContext.tsx`

Пользователь разлогинивается на фронте даже если API вернул ошибку. Сессия в несогласованном состоянии.

---

### 15. AI Assistant — молчаливые ошибки

**Файл:** `src/app/ai-assistant/components/AIAssistantClient.tsx`

Множество fetch-запросов без проверки `response.ok`. Операции тихо проваливаются.

---

### 16. PlateRecognitionDialog — утечка памяти

**Файл:** `src/components/plate-recognition/PlateRecognitionDialog.tsx`

Таймаут не очищается если fetch обрывается. Dangling timeouts накапливаются.

---

### 17. CommentDialog — мутация пропсов

**Файл:** `src/components/common/CommentDialog.tsx`

Прямая мутация `event.driverComments` — нарушает принципы React, вызывает непредсказуемое поведение.

---

### 18. Нет лимитов на числовые поля

**Файлы:** `inventory/route.ts`, `client-transactions/route.ts`, `expenses/route.ts`

Можно поставить отрицательный запас химии, NaN в транзакцию, Infinity в расход. Нет проверок границ.

---

### 19. Path traversal в OCR

**Файл:** `src/app/api/ocr-failed/[filename]/route.ts`

Регулярка `[\w\-]+\.jpg` недостаточна. Нет проверки symlink, нет нормализации пути.

---

### 20. SalaryReportClient — нет состояния ошибки

**Файл:** `src/app/salary-report/components/SalaryReportClient.tsx`

При ошибке Promise.all — вечный спиннер загрузки без сообщения об ошибке.

## Архитектурные рекомендации

**1. База данных.** JSON-файлы — главный источник гонок и потенциальной потери данных. SQLite решит 80% проблем с конкурентным доступом, плюс даст транзакции и индексы.

**2. Аутентификация.** Текущая схема (JSON в cookie) — самая опасная часть системы. Минимум: HMAC-подписанные cookie. Идеал: серверные сессии + hashed passwords.

**3. Валидация.** Zod уже подключён (есть zod-resolver.ts), но используется только на фронте. Добавить Zod-схемы на все API роуты — это убьёт 70% багов валидации.

**4. Обработка ошибок.** Создать middleware для единообразной обработки ошибок, логирования, и санитизации ответов.
