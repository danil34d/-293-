# Журнал БД и взаимодействий

Актуально на: **2026-02-14**

## 1) Модель хранения
- Основное хранилище: файловая БД в `data/*` (JSON по сущностям).
- Отдельная SQLite БД только для AI-модуля: `data/ai-assistant.db`.
- Текущая версия схемы файловой БД: `json-v2` (`data/_meta/schema-version.json`).

## 3) Обязательные потоки

### 3.1 Мойка -> баланс клиента -> склад
1. Создание/изменение/удаление мойки: `/api/wash-events*`.
2. Баланс клиента корректируется через `src/lib/client-balance.ts`.
3. Химия списывается/возвращается в `data/inventory.json`, фиксируется в `data/stock-movements/*`.

### 3.2 Клиентский платеж -> обратная корректировка баланса
1. Операция в `/api/client-transactions/[clientId]`.
2. Запись платежа в `data/client-transactions/<clientId>.json`.
3. Баланс клиента изменяется в противоположную сторону относительно долга по мойкам.

### 3.3 Транзакции сотрудника -> финкарточка и склад
1. Операции в `/api/employees/[id]/transactions`.
2. Запись в `data/employee-transactions/<employeeId>.json`.
3. Для операций выдачи канистры: дополнительное изменение `data/inventory.json`.

## 3.4 Расходы -> склад -> прибыль
1. Создание/изменение/удаление расхода: `/api/expenses*`.
2. Для категории закупки химии обновляется `chemicalStockGrams`.
3. Dashboard считает прибыль как `выручка - расходы`.

### 3.5 Telegram snapshot (read-only агрегатор)
1. Worker вызывает `/api/telegram/internal/snapshot`.
2. Route собирает состояние из `shifts`, `requests`, `employee-transactions`, `wash-events`.
3. Snapshot-cache хранится в `data/telegram-bot/snapshot-cache/*`.

1. `validate-refs`
