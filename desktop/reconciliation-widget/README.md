# Сверка смены ZORIN

Окно владельца для `/reconciliation` в приложении автомойки. Результаты, история и фото журнала сохраняются в PostgreSQL приложения. Заезды читаются через API камер; виджет не меняет записи камер, мойки, кассу или зарплаты.

## Для владельца

1. Сохраните **всю папку** `ZorinReconciliation-win32-x64` в постоянном месте. Запускайте `ZorinReconciliation.exe`.
2. При первом открытии укажите адрес приложения, обычно `http://192.168.1.150:3000`. Включите «Запускать вместе с Windows», если нужен ежедневный виджет.
3. Войдите в обычный кабинет владельца. Сверка откроется после входа. Сотруднику этот экран недоступен.
4. Выберите дату начала и тип смены. Ночь начинается в 20:00 выбранного дня и заканчивается в 08:00 следующего.
5. Добавьте фото журнала при необходимости и перенесите его строки. Фото: JPG, PNG или WebP, до 6 МБ. Новое фото снимает подтверждение прежней сверки; ручные поля сохраняются.
6. В карточке заезда сохраните поля, затем отдельно отметьте результат. Можно связать фрагменты, вернуть их обратно, добавить строку без камеры или оставить вопрос.
7. «Закончить просмотр на сегодня» сохраняет факт просмотра с вопросами. «Завершить сверку» требует внесения всего журнала и разбора всех известных записей.

Крестик прячет окно возле часов. Щелчок по значку открывает его. Полный выход и настройки доступны через меню значка; меню окна также открывается клавишей Alt. В 08:00 по Москве виджет показывает окно; после сна — при пробуждении. Компьютер должен быть включён, Windows запущена. Сохранения остаются на сервере при выключении компьютера; несохранённый ввод нужно сохранить перед выходом.

Автообновление выполняется раз в минуту, когда окно видно и нет несохранённых полей. При изменении исходника снимается только соответствующая отметка проверки. Пропавшая запись остаётся в сверке. Ошибка камеры или базы показывается явно. Успешное чтение API камер не доказывает, что камера записала все машины.

Если другое окно уже изменило смену, устаревшая запись отклоняется. Ввод остаётся на экране: сохраните нужный текст, затем нажмите «Загрузить с сервера» и повторите изменения.

## Подготовка приложения

Нужны `DATA_SOURCE=postgres`, доступ к API камер через `CAMERA_DASHBOARD_BASE_URL` и установленная схема сверки. Добавочная SQL-миграция: `scripts/migrations/reconciliation/001-reconciliation.sql`. Она создаёт три отдельные таблицы и не меняет учёт моек. Выполнять один раз после резервной копии и проверки Git-состояния; миграцию рабочей базы согласовать с владельцем.

После изменения схемы перед сборкой выполнить `DATA_SOURCE=postgres npx prisma generate`. Принятый путь выпуска — PR в актуальную main с merge-коммитом и fast-forward сервера. Исторические скрипты выкладки для этого не использовать. Откат приложения не требует удалять таблицы сверки: сохранённые результаты нужно оставить.

## Сборка Windows

В этой папке: `npm ci`, `npm test`, `npm run package`. Зависимости изолированы от общих `node_modules` основного приложения. Готовая папка находится в `dist/ZorinReconciliation-win32-x64`. Electron и упаковщик закреплены в `package-lock.json`; обновлять их с повторной проверкой окна.

Окно с приложением работает без Node.js в странице, с изоляцией контекста и sandbox. Внешние переходы, новые окна и разрешения устройств запрещены. Настройки имеют отдельное локальное окно с узким каналом чтения/сохранения настроек. Пароль виджет не сохраняет; обычная подписанная cookie входа хранится в его отдельном профиле.

## Проверки

- `npm run test:reconciliation` из корня — модель, браузерное сохранение прежних срезов, живые обновления, запросы и фото.
- `node node_modules/typescript/bin/tsc -p tsconfig.reconciliation-check.json` — строгая проверка кода сверки.
- `node scripts/test-reconciliation-postgres.cjs` — интеграционные транзакции. Требует `P06_TEST_DATABASE_URL` на `localhost`/`127.0.0.1` с базой строго `p06_widget_test`, а также драйвер `pg` в отдельной тестовой папке. Путь можно передать через `P06_PG_DRIVER`. Проверяет гонку первых сохранений, обновление из двух окон, откат истории/фото, часовой пояс и повторное подключение.
- `P06_TEST_SNAPSHOT` указывает на частный локальный срез для проверки старого виджета. Реальные фото, номера и выгрузки не включать в публичный репозиторий.

Проверка самого выпуска должна включать вход владельца, запрет сотруднику, реальную смену, фото/видео, повторное открытие, отключение камер и базы, закрытие в трей и запуск после входа в Windows. Проверка расписания на искусственном времени не равна фактическому наблюдению утреннего открытия.
